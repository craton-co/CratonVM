Section A is the instrument, not a result
-----------------------------------------
A1..A6 agree on both VMs BEFORE the change, and that agreement is the point.
Each line exercises a native the JDK provides no bytecode for, so a correct
answer can only have come from the Rust body:

  * A1/A2 `System.identityHashCode(Object)` is `public static native`. Its Rust
    body reads `args[0]` as the object. If a static native were handed a
    receiver slot, the object would be at `args[1]`, the `_` arm would be taken
    and the answer would be 0 — the same answer A2 legitimately gives for null,
    which is why A1 (comparing against the instance `hashCode()` of the SAME
    object) is the load-bearing line and A2 is only the null control.
  * A5 `Object.wait(long)` is an instance native whose body reads `args[0]` as
    the receiver and `args[1]` as the millis. A body reading the millis from
    the wrong slot sees no timeout and blocks until interrupted.

Both shapes answering correctly in one run is the measurement:

  **`args` carries exactly the descriptor's parameters, preceded by a receiver
  only when the method is an instance method. A zero-parameter static native is
  called with an EMPTY `args`.**

That is what makes B1/B2 a defect rather than a style question, and it was
established from a running VM rather than from the dispatcher's source.


B3 is not repaired here, and says so
------------------------------------
`ExceptionInInitializerError` on B3 is `jdk/internal/vm/Continuation.<clinit>`
refusing with `UnsupportedOperationException: VM does not support continuations`
(via `ContinuationSupport.ensureSupported`) — CratonVM cannot construct a real
`Continuation` at all. That is a separate, larger gap; B1/B2 reach the natives
without it because a registered native is dispatched without running the
class's `<clinit>`. B3 is printed anyway so that "pin/unpin work" is never read
as "continuations work".


C2 is the control
-----------------
`findBootstrapClass` answered null for EVERY name before the change, so C1 alone
cannot distinguish "repaired" from "still broken but the name happened to
resolve". C2 asks for a name that must stay null. A change that turns C1
non-null and C2 non-null has not fixed the argument index — it has removed a
refusal.

Everything else was already identical, which is the point: an over-grant and a
correct grant BOTH leave `toSelf=true` and both let the access through. Only
the unqualified queries — `Module.isExported(pkg)` / `Module.isOpen(pkg)` —
distinguish them, so a probe that asserts on "did the reflection work" cannot
see this bug at all.

Cause: `addExportsToAllUnnamed0`, `implAddExportsToAllUnnamed` and
`implAddOpensToAllUnnamed` all recorded the edge with an empty target, and an
empty target is `ModuleRegistry`'s *unqualified* marker (grant every module).
They now pass `classloading::module::ALL_UNNAMED_TARGET`, which resolves to a
qualified edge naming the unnamed module.

Why the fix cannot reopen the IllegalAccessError vector that originally
justified the widening: that vector came from *dropping* the edge. This does
not drop it — `export after toSelf=true` above is the grant to the unnamed
module, and classpath code lives in the unnamed module. What changes is only
that named modules stop receiving a grant HotSpot never gave them.

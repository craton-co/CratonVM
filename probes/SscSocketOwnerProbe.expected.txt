W7-88 — SscSocketOwnerProbe, measured 2026-08-12 on Windows 11.

EVERY LINE IS NO-CHANGE. This probe is an INSTRUMENT, not a result. W7-88
deletes a native registration that is not present in any runnable
configuration's registry, so there is no behaviour it can move. The probe
exists for one thing the source cannot say: it drives
`ServerSocketChannel.socket()` so that the `--dump-native-registry` census can
name the row that actually served the call, by invocation count.

  javac -d out probes/SscSocketOwnerProbe.java
  java  -cp out SscSocketOwnerProbe

Every value is read back through a real JDK accessor (`getClass`, `isClosed`,
`isBound`, `getLocalPort`, `isOpen`) rather than through the native that wrote
the field, which is the W7-72 rule. `socket.class` is the load-bearing line:
`sun.nio.ch.ServerSocketAdaptor` is the JDK's own adaptor, so the view is the
one `native-io`'s `ssc_socket` builds -- not a fabricated `java.net.ServerSocket`
of the shape the deleted `net_channels.rs` body allocated.

The census taken on THAT SAME RUN (`--dump-native-registry`), which is the
actual finding:

     registered_by = native-io/src/socket_channel.rs:4776
     owns_slot     = true

`invocations = 1` says the probe's call reached THIS row. `overwrote = null`
says no earlier registration was displaced -- the `net_channels.rs` body was
never registered at all, in this or any other runnable configuration.

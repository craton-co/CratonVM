# Spring Boot suite rerun — 2026-07-13

Full rerun of the 1975-class suite against a fresh binary built from current
`dev` (`71f1516e1`), after the 7 bug clusters found in the first run
(2026-07-11, see `RESULTS-20260711.md`) were fixed by concurrent sessions on
this shared host.

- **Binary:** `cratonvm-spring-boot-suite.exe`, built from worktree
  `C:\craton\CratonVM-spring-boot-rerun-20260713` (branch
  `feat/spring-boot-suite-rerun-20260713`, off `dev` @ `71f1516e1`).
- **Note:** the original `feat/spring-boot-suite-runner-20260711` worktree
  and its `.suite/results/` were deleted in a disk-space-recovery sweep of
  this shared host between sessions, so this is a **full rerun**, not a
  precise "non-passed only" rerun — a strictly equivalent (and more
  complete) way to verify the fixes given the original per-class result
  list no longer exists.
- **Sharding:** 8 shards of ~247 classes each, `-Parallel 2` per shard,
  `-TimeoutSec 300`, `RunName=rerun-20260713`. Wall time ~2h38m (max shard
  9498s).

Confirms real, substantial improvement from the concurrent dev fixes for all
7 previously-documented clusters (`OnClassCondition` NPE, `DisposableBeanAdapter`
destroy-method resolution, `Unsafe$MemoryAccessOption` NPE, `HttpClient.Builder`
dead registration, `spring-boot-loader` zip AIOOBE, the Flyway CGLIB heap
corruption, and the `TestCompiler` annotation-classpath gap) — CRASH more
than halved, FAIL down ~20%, PASS up ~11%. HANG is essentially unchanged,
consistent with the HANG-rerun finding that most of that bucket (60% at 5x
timeout) is a genuine, separate long-tail of slow/stuck classes not
addressed by these fixes.

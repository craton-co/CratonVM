# Spring Boot Suite Runner

`run-spring-boot-suite.ps1` runs the compiled Spring Boot JUnit suite under
CratonVM or HotSpot, one process per test class. It uses:

- Spring Boot checkout: `apps\spring-boot` (Spring Boot 4.1.0-SNAPSHOT / Spring
  Framework 7.0.7, restored from the checkout's own git history — see
  "Restoring the checkout" below)
- JUnit Platform runner: `apps\spring-boot\sb-runner\SbRunner.class` (mirrors
  `apps\keycloak\kc-runner\KcRunner.class`)
- Per-module test classpaths generated by the Gradle init script
  `apps\spring-boot\cratonvm-test-cp.init.gradle` (writes
  `<module>\build\cratonvm-test-cp.txt` for every project with a `test`
  source set — the Gradle analogue of Keycloak's Maven
  `dependency:build-classpath`)

Every class gets wall-clock timing and persisted stdout/stderr logs.

## Restoring the checkout

`apps\spring-boot` is a real `spring-projects/spring-boot` clone. To save disk
on this shared host, most of its tree (everything except `buildSrc`,
`build-plugin`, `buildpack`, and the CratonVM-specific
`cratonvm-suite`/`cratonvm-bug-reports` additions) was previously staged as
deleted but never committed — the content is still in the checkout's own git
HEAD. If `core`, `module`, `cli`, `configuration-metadata`, `loader`,
`test-support`, `documentation`, `smoke-test`, `integration-test`, and
`system-test` are missing, restore them with:

```powershell
cd apps\spring-boot
git config core.longpaths true   # required — some module test-resource paths exceed 260 chars
git checkout HEAD -- settings.gradle gradle core module starter cli test-support `
  configuration-metadata loader config platform documentation smoke-test integration-test system-test
```

Do **not** run `git checkout HEAD -- buildSrc build-plugin buildpack` — those
three already exist on disk with CratonVM-specific customizations that differ
from upstream HEAD; checking them out would silently revert those edits.

## Prerequisites

- `apps\spring-boot\sb-runner\SbRunner.class` — compile once:
  ```powershell
  cd apps\spring-boot\sb-runner
  $env:JAVA_HOME = 'C:\Program Files\Java\jdk-25'
  # Find junit-platform-launcher/-engine/-commons, junit-jupiter-api,
  # opentest4j, apiguardian-api in ~\.gradle\caches\modules-2\files-2.1\...
  # (versions must match gradle.properties' junitJupiterVersion) and:
  & "$env:JAVA_HOME\bin\javac.exe" -cp "<those jars joined by ;>" SbRunner.java
  ```
- `apps\spring-boot\gradlew` / `gradlew.bat` (Gradle 9.5.0 wrapper, already
  cached under `~\.gradle\wrapper\dists`)
- JDK 25 at `C:\Program Files\Java\jdk-25`, or pass `-JdkHome`
- For CratonVM runs, a uniquely named executable. The runner looks for:
  1. `-Exe <path>`
  2. `$env:CV_BIN`
  3. `$env:CRATONVM_SPRING_BOOT_EXE`
  4. `target\release\cratonvm-spring-boot-suite.exe`

  If only `target\release\cratonvm.exe` exists under the repo root, the
  runner copies it to `target\release\cratonvm-spring-boot-suite.exe` and
  uses that copy, avoiding accidental cleanup of unrelated `cratonvm.exe`
  processes from other sessions.

## One-time setup

`-Setup` compiles test classes and generates classpaths across the
`-Subtrees` list (default: `core`, `module`, `cli`,
`configuration-metadata`, `loader`, `test-support` — **not**
`smoke-test`/`integration-test`/`system-test`/`documentation`, which need
Docker or are non-test doc-build modules), then builds the class list:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File apps\spring-boot-suite-runner\run-spring-boot-suite.ps1 -Setup
```

This can take 10-30+ minutes cold (Gradle dependency resolution across ~150
modules) but is fast on a warm `~\.gradle` cache (mostly `FROM-CACHE`/
`UP-TO-DATE`). Re-run `-Setup` any time the checkout or module set changes;
Gradle tasks no-op when nothing changed.

## Basic Commands

Show the first five discovered classes:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File apps\spring-boot-suite-runner\run-spring-boot-suite.ps1 `
  -RefreshLists -Category all -Start 1 -Count 5 -ListOnly
```

Capture a full HotSpot baseline:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File apps\spring-boot-suite-runner\run-spring-boot-suite.ps1 `
  -Vm hotspot -Category all -RunName hotspot-baseline-20260711 -Parallel 4
```

Run the full CratonVM suite, JIT on:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File apps\spring-boot-suite-runner\run-spring-boot-suite.ps1 `
  -Vm craton -Category all -Jit on -RunName craton-jiton-20260711 -Parallel 4
```

Run classes 501-1000 only:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File apps\spring-boot-suite-runner\run-spring-boot-suite.ps1 `
  -Category all -Start 501 -Count 500 -RunName slice-501-1000
```

## Parameters

| Parameter | Values | Default | Purpose |
|---|---|---:|---|
| `-Category` | `passed`, `others`, `failed`, `all` | `all` | Class set to run. `failed` is an alias for `others`. |
| `-Jit` | `on`, `off` | `on` | `off` adds CratonVM `--nojit`; HotSpot uses `-Xint`. |
| `-Vm` | `craton`, `hotspot` | `craton` | VM to run. |
| `-Start` | integer >= 1 | `1` | 1-based start index within the selected category. |
| `-Count` | integer >= 0 | `0` | Number of classes to run; `0` means through the end. |
| `-Parallel` | integer >= 1 | `4` | Concurrent class processes per mode. |
| `-TimeoutSec` | integer >= 1 | `300` | Per-class timeout. Timeout status is `HANG`. |
| `-RunName` | string | timestamp | Result directory name. |
| `-SpringBootRoot` | path | sibling `apps\spring-boot` | Spring Boot checkout to run. |
| `-WorkDir` | path | `apps\spring-boot-suite-runner\.suite` | Generated lists, results, logs, baselines. |
| `-RefCsv` | path | auto | Reference results for passed/others split. TSV or CSV accepted. |
| `-Subtrees` | string array | `core,module,cli,configuration-metadata,loader,test-support` | Gradle subtrees to compile/discover classes in. |
| `-Exe` | path | auto | Unique CratonVM executable. |
| `-JdkHome` | path | `$env:JAVA_HOME`, then JDK 25 default | JDK for HotSpot and CratonVM `--java-home`. |
| `-MaxHeap` | heap string | `2g` | Heap passed to both VMs. |
| `-CratonArgs` | string array | none | Extra CratonVM CLI arguments. |
| `-RefreshLists` | switch | off | Rebuild `all-tests.tsv`, `passed.tsv`, `others.tsv` from currently-compiled classes. |
| `-RefreshClasspaths` | switch | off | Force-regenerate a module's `cratonvm-test-cp.txt` even if cached. |
| `-ListOnly` | switch | off | Print selected classes without running. |
| `-AllModes` | switch | off | Run JIT on/off concurrently (each a background PowerShell child). |
| `-Setup` | switch | off | Compile test classes + generate classpaths across `-Subtrees`, then build class lists. |

## Classpath model

Each test class is launched with its **module's** Gradle test runtime
classpath (`<module>\build\cratonvm-test-cp.txt`, generated by
`cratonvm-test-cp.init.gradle`), plus `sb-runner\` (for `SbRunner.class`)
and the JUnit Platform launcher/engine/opentest4j/apiguardian jars — located
by scanning `~\.gradle\caches\modules-2\files-2.1\...` — since a module's own
`testRuntimeClasspath` does not necessarily include the launcher jar (Gradle's
own `test` task manages that on its internal tooling classpath, not the
project's).

When a module's classpath is too long for a Windows process command line, the
runner writes a small pathing JAR under `.suite\pathing-jars\` and launches
both HotSpot and CratonVM with `-jar`/`--jar` against it instead of `-cp`.

Any `CRATONVM_*` environment variable already set in the shell is inherited by
every CratonVM child process.

## Passed vs Others

`passed` means the class had `status=PASS` in a CratonVM reference result
file. Every other discovered class is `others`, including `FAIL`, `CRASH`,
`HANG`, `LOADFAIL`, `EMPTY`, and classes absent from the reference.

Reference file lookup order: `-RefCsv <path>` → `.suite\reference.tsv` →
`.suite\reference.csv`.

## Output Layout

```text
.suite\
  all-tests.tsv / passed.tsv / others.tsv     module<TAB>class
  results\<RunName>\<ModeName>\
    results.tsv
    summary.md
    logs\
      <module>.<class>.out.log
      <module>.<class>.err.log
  baseline\hotspot-baseline-<RunName>.tsv / .md   (Vm=hotspot runs only)
  pathing-jars\                                    (long-classpath fallback)
  classpaths\                                       (unused; classpaths live under each module's build\)
```

`results.tsv` columns: `index, module, class, vm, jit, rc, status, seconds,
tests, failed, aborted, skipped, containersFailed, stdoutLog, stderrLog, note`.

Status values: `PASS`, `FAIL` (failed/aborted tests or failed containers),
`EMPTY` (ran, zero tests), `LOADFAIL` (class load failed), `HANG` (hit
`-TimeoutSec`), `CRASH` (crash/panic fingerprint or non-zero exit with no
`SBRUNNER_RESULT` line), `NOSUMMARY` (neither).

Runs are resumable — existing rows in `results.tsv` are skipped when
rerunning the same `-RunName` and mode.

## Known gaps

- `smoke-test`, `integration-test`, `system-test` are **not** in the default
  `-Subtrees` — many need Docker/Testcontainers or a packaged/running Spring
  Boot app, outside the one-process-per-class JUnit-launcher contract. Pass
  `-Subtrees` explicitly to include them if you have Docker available.
- `documentation` is doc-build tooling, not application test coverage; not
  included by default.

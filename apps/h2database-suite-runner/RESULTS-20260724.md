## Setup snag: `target/` had been swept

The first attempt at this run failed instantly on **every** class
(`Could not find or load main class ...: class not found`) — `apps/h2database/h2/target/`
(the compiled main+test classes from the previous session's `setup`) was
gone entirely, most likely an automated disk-cleanup pass on this shared,
frequently-disk-constrained host (`target/` matches this repo's own
`.gitignore`, and free space had grown from ~22G to ~74G between sessions
without any cleanup done by this session). Re-ran
`MVN_JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./run-h2-suite.sh setup`
(fast — Maven's local `~/.m2` cache made recompilation take ~7s) and the
suite ran normally after that. Worth remembering: `apps/h2database/h2/target/`
is not guaranteed to survive between sessions on this host even within the
same worktree — always safe to blind-run `setup` before a suite run rather
than assuming last session's build artifacts are still there.

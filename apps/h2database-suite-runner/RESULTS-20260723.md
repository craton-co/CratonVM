## Runner bug found and fixed while sharding

`list_for_category()`'s `--shard` handling used
`local i="${SHARD%/*}" m="${SHARD#*/}" f="$META/.shard-${i}of${m}-$$.tsv"` —
a single `local` statement where the third assignment's value expands `$i`
and `$m` from the *same* statement. Under `set -u` this reliably failed with
`i: unbound variable`, so every `--shard` invocation silently produced an
empty class list (`nothing to run`) instead of erroring loudly. Fixed by
declaring `local i m f` first and assigning each on its own line. (A CRLF
line-ending regression from editing the script on Windows also broke `#!/usr/bin/env
bash` on the Linux host along the way — re-saved with LF endings.)

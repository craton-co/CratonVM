# Boot image static classification (Phase 5 WP7; `statics.rs`).
#
# Every launcher-binary static and `main-vm` thread-local that a capture run's
# boot changes between P0 and P1 must be named here, or the capture refuses to
# write an image (`CRATONVM_BOOT_IMAGE=auto,verbose` names the owner;
# `auto,verbose,census` lists every owner with its class). Lines:
# `<class> <pattern>`; first match wins; `X*` prefix, `*X` suffix, `*X*`
# substring, else exact. Names are demangled (v0: identifiers only, crate
# disambiguators dropped).
#
#   keep     restore-correct: the capture's value is valid after restore
#   exclude  exclude-and-reinit: never copied; the restored process keeps its
#            own value (lazily re-initialised, or rebound by the restore path)
#   refuse   must be initialised before P0; a change refuses the image

# ---- exclude-and-reinit -----------------------------------------------------
# The allocator of the restored process (mimalloc's C statics: main heap,
# sub-process, segment-address hint). Never entered P0..P1 (the capture arena
# serves every allocation), but the snapshot/diff machinery itself allocates;
# the restored process must keep its own allocator state.
exclude heap_main
exclude subproc_main
exclude subprocs_lock
exclude aligned_base*
exclude _mi_*
exclude mi_*
# Process-start clocks behind `RuntimeMXBean.getStartTime/getUptime`: lazily
# re-initialised in the restored process. (`lang_system::java_time_nanos::START`
# is kept on purpose: `System.nanoTime` values the boot stored must stay below
# later readings, and CLOCK_MONOTONIC is system-wide.)
exclude cratonvm_native_builtins::jmx::PROCESS_START
exclude cratonvm_native_builtins::jmx::PROCESS_START_EPOCH_MS

# ---- refuse -------------------------------------------------------------------
# Must be initialised before P0 (a change would carry the capture process's
# identity): none known today. Add an owner here to make its change refuse.

# ---- thread-locals of main-vm ------------------------------------------------
# Per-thread memos about the VM in the image (class ids, layouts, resolution
# selections, the thread's own state cell and registrations): the restored
# main-vm is the same VM thread, and its TLS block is at the same address (the
# key pins it). Bytes no TLS symbol covers are thread_local! storage the
# linker left unnamed.
keep *::__RUST_STD_INTERNAL_VAL
keep ?tls

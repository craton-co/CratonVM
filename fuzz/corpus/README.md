# Fuzz Corpora

`cargo fuzz` creates and grows `fuzz/corpus/<target>/` as targets run. The
directories below hold **committed hand-built seeds**: structurally valid
examples of each target's per-input layout, so libFuzzer starts from a shape
that already reaches deep code instead of from random noise.

Everything under `fuzz/corpus/` is regenerated by
[`gen_seeds.py`](gen_seeds.py) (standard library only):

```sh
python fuzz/corpus/gen_seeds.py
```

It is idempotent — byte-for-byte, verified across consecutive runs — and
only needs re-running when a target's per-input layout changes. The seeds
are binary, so the script is the readable source of truth for what each one
encodes.

Idempotency is load-bearing, not cosmetic: CI regenerates the corpus and
fails on `git diff`, which catches the case where a layout changes and
nobody re-runs the generator. It also has one sharp edge worth knowing
about — `zipfile.writestr(name, data)` stamps `time.localtime()` into the
`ZipInfo`, so the `fuzz_zip_entry` seeds were rewritten differently on
every run until `zip_entry()` started pinning `date_time` and
`create_system`.

## Committed seeds

### `fuzz_constant_pool/`

Layout: `this_class` u2 | `super_class` u2 | raw constant pool.

| Seed                      | What it encodes                                                                                                             |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `seed-coherent-pool`      | A pool whose `this_class` / `super_class` resolve, so `read_class` returns `Ok` and every accessor assertion actually runs.  |
| `seed-category2-and-refs` | `Long` + `Double` (two slots each), `MethodHandle`, `InvokeDynamic`, `Module`, `Package`, `MethodType` — the widest `validate()` walk. |
| `seed-absurd-count`       | `constant_pool_count = 65535` backed by three bytes. The anti-OOM shape: must fail without allocating 65 535 entries.        |

### `fuzz_attribute_nesting/`

Layout: selector byte | raw attribute body.

| Seed                         | What it encodes                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------- |
| `seed-code-in-code`          | A three-deep `Code`-in-`Code` body — valid, inside the depth cap, and the shape to deepen.  |
| `seed-nested-annotations`    | `RuntimeVisibleAnnotations` with four levels of `@`-nested `element_value`s.                 |
| `seed-type-annotation-path`  | `RuntimeVisibleTypeAnnotations` with a 3-entry `type_path` and a `[`-array element value.    |

### `fuzz_jni_descriptor/`

Layout: selector byte | scale byte | free-form descriptor text.

| Seed                      | What it encodes                                                             |
| ------------------------- | ----------------------------------------------------------------------------- |
| `seed-method-descriptor`  | `(Ljava/lang/String;[[IJZ)Ljava/util/Map;` — mixed reference/array/category-2. |
| `seed-generic-signature`  | A class signature with a type parameter, a parameterised bound, and an interface. |
| `seed-array-nesting`      | 200 array dimensions (legal) over an object component.                        |

### `fuzz_jfr_chunk/`

Layout: the chunk body — a whole `.jfr` file *minus* its 4-byte `FLR\0`
magic, which the harness prepends.

| Seed                        | What it encodes                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------------------- |
| `seed-one-scalar-event`     | A well-formed record of registry type 1 (`long`, `int`, `boolean`, `float`, `double`).                  |
| `seed-offsets-past-eof`     | `checkpoint_offset` and `metadata_offset` set to `u64::MAX` — both must be rejected before any slicing. |
| `seed-record-size-overflow` | A record declaring `u64::MAX` bytes: the `checked_add` overflow guard's reason for existing.            |

### `fuzz_zip_entry/`

Layout: the raw archive bytes.

| Seed                    | What it encodes                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `seed-plain-jar`        | An ordinary JAR: manifest with `Main-Class` and `Class-Path`, one class entry, one resource.                             |
| `seed-traversal-names`  | Entry names spelling `../`, `..\`, absolute, drive-letter, `./`, and invalid UTF-8. Drives the traversal oracle directly. |
| `seed-ratio-bomb`       | 4 MiB of zeros deflated into ~2 KiB — exercises the streaming-inflate accounting under the 512 MiB clamp.                 |
| `seed-truncated`        | A valid archive with its tail removed, so end-of-central-directory discovery must fail cleanly.                          |

### `fuzz_signed_jar/`

Layout: selector | `manifest_len` u2 | `sf_len` u2 | manifest | `.SF` | signer block.

| Seed                      | What it encodes                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `seed-pkcs7-signeddata`   | A real `MANIFEST.MF` + `.SF` pair plus a minimal, deliberately truncated PKCS#7 `signedData` `ContentInfo`.        |
| `seed-bad-algorithms`     | Unsupported (`MD5`, `SHA-999`) algorithms, malformed base64, a 5 KiB entry name past the 4 KiB cap, and a `.SF` carrying only `-Digest-Manifest-Main-Attributes` (not a valid substitute). |
| `seed-pem-bundle`         | A PEM anchor bundle in the signer-block slot, routing to `TrustStore::load_pem_bundle`.                            |

### `fuzz_classfile/`, `fuzz_read_class/`, `fuzz_verifier/`, `difftest_bytecode/`

Layout: a whole `.class` file, no framing.

`valid_class()` in the generator mirrors
`reader/tests/mutation_harness.rs::valid_class` structure for structure —
same constant pool, same single `void m()` with a non-empty exception
table, same nested `LineNumberTable` + `StackMapTable`, same class-level
`SourceFile`. That fixture is driven through `force_decode_all` and
`verified_code` by the ordinary test suite on every commit, so a seed built
the same way is known-good rather than hoped-good. `seed-valid-class` is
218 bytes, which is the length `mutation_coverage_totals_are_exact` pins.

| Seed                       | What it encodes                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `seed-valid-class`         | The baseline class. Parses, and every lazy attribute decoder decodes.                                                |
| `seed-switch-code`         | A `Code` body holding `tableswitch` and `lookupswitch` at pcs whose 4-byte alignment padding differs.                 |
| `seed-stack-map-families`  | A `StackMapTable` using all five frame families plus `Object` and `Uninitialized` verification types.                |
| `seed-java21`              | The baseline at `major = 65`, so the class-file-version gate is a seeded branch rather than one the mutator must find. |
| `seed-numeric-constants`   | (`difftest_bytecode` only) `Integer`, `Float`, `Long`, `Double` in one pool — without these the mutator has nothing to rewrite and the length-preservation assertion never runs. |

### `fuzz_stack_map/`

Layout: the raw `StackMapTable` attribute body (everything after
`attribute_name_index` and `attribute_length`).

| Seed                          | What it encodes                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------------- |
| `seed-all-frame-kinds`        | `same`, `same_locals_1_stack_item`, `chop`, `append`, and `full_frame` in one table.                  |
| `seed-offset-delta-overflow`  | Four `chop_frame`s of delta 65535: `absolute_offsets` must return `Err`, not wrap.                    |
| `seed-absurd-entry-count`     | `number_of_entries = 65535` backed by two bytes. The anti-OOM shape.                                  |
| `seed-unbacked-append`        | An `append_frame` declaring three extra locals with none behind it.                                   |

### `fuzz_instruction/`

Layout: the whole input is one bytecode array, walked from pc 0.

| Seed                           | What it encodes                                                                                    |
| ------------------------------ | -------------------------------------------------------------------------------------------------- |
| `seed-switches`                | `tableswitch` then `lookupswitch`, both alignment-padded, at differing pcs.                         |
| `seed-wide-forms`              | `wide iload` / `wide istore` (4 bytes) and `wide iinc` (6 bytes) — one prefix, two operand widths.  |
| `seed-operand-shapes`          | `bipush`/`sipush`/`ldc`/`ldc_w`/`ldc2_w`, `newarray`, `multianewarray`, `invokeinterface` (count + reserved byte), `invokedynamic` (two reserved zeros), `goto`, `goto_w`. |
| `seed-truncated-tableswitch`   | A `tableswitch` header claiming 65536 jump offsets that are not present.                            |

### `fuzz_descriptor/`

Layout: the whole input, lossily decoded as UTF-8.

| Seed                      | What it encodes                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------- |
| `seed-method-descriptor`  | A mixed reference / array / category-2 method descriptor.                                    |
| `seed-class-signature`    | Two type parameters, one with an interface bound, plus a parameterised superclass.           |
| `seed-method-signature`   | A wildcard argument, an array of a type variable, and two `throws` clauses.                  |
| `seed-field-signature`    | A nested parameterised type with an inner-class (`.Entry`) suffix.                           |
| `seed-modified-utf8`      | A CESU-8 surrogate pair and a lone high surrogate inside a class name.                       |

### `fuzz_jimage/`

Layout: a whole jimage container. The generator mirrors
`reader/src/jimage::test_builder` — 28-byte little-endian header, redirect
table, offset table, locations buffer (offset 0 is a reserved sentinel),
NUL-terminated strings buffer, resource data — including the
multiply-then-xor FNV hash and the single-step `redirect = -(slot + 1)`
assignment, so lookups actually resolve.

| Seed                        | What it encodes                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `seed-two-resources`        | Two resources whose paths `iter_entries` reconstructs and `find_resource` resolves. Without this the fuzzer essentially never builds a header that survives `from_bytes`, and every iteration bails on the magic. |
| `seed-absurd-table-length`  | The same image with `table_length = 0xFFFFFFFF`: section-offset arithmetic must fail closed.                            |
| `seed-header-only`          | The 28-byte header with every section cut away.                                                                        |

### `fuzz_asn1/`

Layout: selector byte (`% 5` picks the decoder) | DER payload.

| Seed                         | Decoder                          | What it encodes                                                    |
| ---------------------------- | -------------------------------- | ------------------------------------------------------------------ |
| `seed-long-form-length`      | `read_header`                    | A two-byte long-form length (300-byte OCTET STRING).                |
| `seed-oid`                   | `read_oid`                       | A first arc packing two components, plus multi-byte base-128 arcs.  |
| `seed-algorithm-identifier`  | `decode_algorithm_identifier`    | `ecPublicKey` + `prime256v1`.                                       |
| `seed-spki`                  | `decode_subject_public_key_info` | A full SubjectPublicKeyInfo with an uncompressed EC point.          |
| `seed-extensions`            | `decode_extensions`              | `basicConstraints` (critical) and `keyUsage`.                       |
| `seed-certificate`           | `parse_certificate`              | A v3 Certificate shell — version, serial, RDNs, validity, SPKI, extensions — with a garbage `signatureValue`, so the parser walks the whole structure before rejecting. |

### `fuzz_keystore/`

Layout: selector byte (`% 3`) | password-length byte | password | body.

| Seed                     | What it encodes                                                                                              |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `seed-jks`               | `FEEDFEED`, one private-key alias record with a certificate chain, then a non-verifying HMAC-SHA1 trailer. Reaching the HMAC check means every record above it parsed. |
| `seed-jks-sniffed`       | The same bytes routed through `load_keystore`, so the magic sniffer decides.                                  |
| `seed-pkcs12`            | A PFX shell: version, `authSafe` ContentInfo, `macData` with a SHA-1 algorithm and an 8-byte salt.            |
| `seed-pkcs12-sniffed`    | The same, through the sniffer.                                                                                |
| `seed-unknown-magic`     | Neither magic — the sniffer must reject rather than guess.                                                    |

### `fuzz_tls_record/`

Layout: raw wire bytes — `u1 content_type | u2 legacy_version | u2 length | fragment`.

| Seed                        | What it encodes                                                                                     |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| `seed-handshake`            | A handshake record carrying a ClientHello-shaped body — the first bytes a server ever decodes.       |
| `seed-max-fragment`         | Application data at exactly the 16384-byte spec ceiling.                                             |
| `seed-length-overrun`       | A declared length of `0xFFFF` with nothing behind it.                                                |
| `seed-two-records`          | Two records back to back; the decoder must consume exactly the first.                                |
| `seed-unknown-content-type` | An unknown content type in an otherwise legal frame — rejection must be on the type, not the framing. |

## Real-world seeds

The generated seeds are structurally valid but narrow: they encode the
shapes a hand-written generator thought of. Drop real files in alongside
them, and they will be picked up on the next run:

- `fuzz_classfile` / `fuzz_read_class` / `fuzz_verifier` / `difftest_bytecode`
  — real `javac` output, e.g. `fuzz/corpus/fuzz_classfile/Object.class`.
- `fuzz_jimage` — the bootstrap `modules` jimage truncated to a few MiB.
- `fuzz_keystore` — a real self-signed JKS or PKCS#12.
- `fuzz_asn1` — a real DER-encoded X.509 certificate (prefix it with the
  selector byte `\x04` so it routes to `parse_certificate`).
- `fuzz_tls_record` — a captured TLS record.
- `fuzz_signed_jar` — the three files out of a real `jarsigner` output,
  reframed with the target's two `u16` length prefixes.

## Regressions

When a bug is fixed, commit the minimized reproducer under the matching
target directory with a descriptive `regression-` prefix:

```text
fuzz/corpus/fuzz_classfile/regression-nested-code-attribute
```

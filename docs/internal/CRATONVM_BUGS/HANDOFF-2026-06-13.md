## TL;DR

Re-ran the full 651-class Tomcat 12 JUnit suite under CratonVM vs HotSpot. Found
and fixed **5 general CratonVM defects** (all the same shape: a native shadows a
real JDK method but assumes a *synthetic* field layout / a process-global cache
isn't a GC root). Net effect on CratonVM: **silent VM aborts (NOSUMMARY) 229 → 13**,
**+14 fully green, 0 regressions**. The recovered embedded-server tests now start
and serve HTTP 200, but are interpreter-slow → many land in HANG (a throughput
limit, not a defect).

## Fixes landed (verified, 0 regressions vs loop1→loop3)

| Bug | File(s) | Root cause → fix |
|-----|---------|------------------|
| **R** [BUG-R](BUG-R-jul-logger-getname-slot0.md) | `native-builtins/src/lib.rs` | `Logger.getName()` native read instance slot 0 → on real-JDK loggers that's `config` (`Logger$ConfigurationData`), so `ClassLoaderLogManager.addLogger`'s `getName().lastIndexOf('.')` threw `NoSuchMethodError` and **aborted 171 server-test classes**. Fix: read the real `name` field by name, slot-0 fallback for synthetic loggers. |
| **S** [BUG-S](BUG-S-classloader-getsystemclassloader-null.md) | `native-builtins/src/classloader.rs` | Synthetic app/platform `ClassLoader` set `name`/`parent` by *slot*, but the active getters read by *name*; real static `scl` never set → `WebappClassLoaderBase.<init>` `getParent` NPE → **every webapp deploy failed**. Fix: set `name`/`parent` by name + populate `java.lang.ClassLoader.scl`. |
| **T** [BUG-T](BUG-T-modulelayer-modules-synthetic-hashset.md) | `native-builtins/src/jboss_jdkspecific.rs` | `Configuration.modules()` returned a *synthetic* `HashSet` whose real `iterator()` is null → `StandardJarScanner.doScanClassPath` `hasNext` NPE → **every context's web-fragment scan failed**. Fix: return a real empty `HashSet` via its ctor. |
| **StringWriter** | `native-io/src/lib.rs` | `StringWriter.getBuffer()` was aliased to the toString native → returned a `String`, so Derby `ErrorStringBuilder.reset()` `getBuffer().setLength(0)` threw `NoSuchMethodError String.setLength`. Fix: new `native_sw_get_buffer` returning a real `StringBuffer`. |
| **U** [BUG-U](BUG-U-stale-locale-gc-root-sigsegv.md) | `native-builtins/src/{lib,locale_bootstrap}.rs`, `vm/src/memory/{roots,gc}.rs` | Cached default `java.util.Locale` (+ side-tables) held raw `ObjectRef`s that were **not GC roots / not remapped** → moving young GC reclaimed/relocated them → stale-pointer **SIGSEGV** (`TestServerInfo` CRASH→PASS). Fix: `gc_scan_locale_roots` / `gc_update_locale_refs`, wired into the GC like the class-loader singleton roots. |

All five are the **same class as the pre-existing BUG-J / StringBuilder /
BufferedWriter shadow bugs**: in real-JDK mode a native must read fields by name
(or run real bytecode) and any process-global Java-object cache must be a GC
root + remap target.

## Harness fix (important for honest numbers)

`run-suite.ps1` ran the per-class JVM with CWD = `.tooling/` instead of the
Tomcat base, so tests that load test webapps/resources by *relative* path
(`test/webapp`, `webapps/examples`, SSL keystores) failed on **both** VMs
(`Unable to create WebResourceSet …`, `NoSuchFileException …\.tooling\test\webapp`).
This inflated HotSpot's failures to ~172 and masked real CratonVM crypto gaps.
**Fixed**: added `-WorkingDirectory $TC` to the `Start-Process` call. Always diff
two runs taken under the *same* harness config (`diff-runs.sh` defaults to the
clean `full/hotspot` baseline — pass `HS_CSV=` to override).

> Note: the per-class background PowerShell runner sometimes exits early
> (`exit code 4`) mid-suite. The runner is **resumable** (appends to
> `results/<tag>/<vm>/results.csv`, skips done classes) — just re-invoke the same
> command to continue.

   `TestHttpServletDoHead*` family (64 variants) exceeds even a **300 s**
   timeout. Needs JIT on the per-class JUnit path or a much higher timeout — not
   a correctness fix. Don't mis-file these as bugs.
2. **HTTP-serving FAIL (~113)** — embedded contexts now start; remaining
   failures are serving/assertion correctness (some classes fail only 1–2 of
   many methods). Triage individually.

   `no KeyStore JKS` (`TestSsl`, `TestSSLHostConfig*`, `TestClientCertTls13`,
   `TestCustomSsl`, `TestAlpnFallback`). CratonVM has no TLS server stack; route
   `KeyManagerFactory`/`TrustManagerFactory`/`KeyStore JKS`/`SSLContext` to a
   real provider (large effort) — see `build_jca_instance` in
   `native-builtins/src/jca/provider_chain.rs`.
4. **Hard crashes (open):**
   - `TestSwallowAbortedUploads` — SIGSEGV in the file-upload buffer path; the
     Bug-D **conservative-JIT-root / young-GC** family (see

     "registry/mark-word desync" under multi-threaded lock churn ([BUG-V](BUG-V-monitor-registry-markword-desync.md)).

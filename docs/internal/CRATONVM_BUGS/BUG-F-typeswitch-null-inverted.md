# BUG-F — pattern `switch` `case null` / no-match indices inverted (`SwitchBootstraps.typeSwitch`/`enumSwitch`)

**Tests:** `jakarta.el.TestOptionalELResolver` (3 failures),
`jakarta.el.TestResourceBundleELResolver` (toString-on-null failure), and any
modern-Java code that uses a pattern `switch` with `case null`.
**Symptom under CratonVM:** `ELException: java.lang.NullPointerException: Cannot
invoke toString on null` — HotSpot: PASS.

## Root cause

`org.apache.el.lang.ELSupport.coerceToString` ends with a Java 21 pattern
switch:

```java
return switch (obj) {
    case null   -> "";
    case String s -> s;
    case Enum<?> e -> e.name();
    default -> obj.toString();
};
```

javac compiles this to `invokedynamic SwitchBootstraps.typeSwitch(obj, 0)`
followed by `tableswitch { // -1 to 1 ... }`. The bootstrap contract is:

| target            | return value      | source arm        |
|-------------------|-------------------|-------------------|
| `null`            | **-1**            | `case null`       |
| matches label *i* | *i*               | that case         |
| matches no label  | **labels.length** | `default`         |

CratonVM's `execute_type_switch` / `execute_enum_switch`
(`vm/src/runtime/invokedynamic.rs`) had these two return values **inverted**:
it returned `labels.len()` for a null target and `-1` for a non-matching target.
So `coerceToString(null)` fell through to the `default` arm and ran
`null.toString()` → NPE, instead of selecting `case null -> ""`.

A stale comment even claimed *"callers that want `case null` handling must check
the pattern before invoking the bootstrap"* — but javac-generated bytecode never
does that; it relies on the bootstrap returning -1.

## Fix

`vm/src/runtime/invokedynamic.rs`: return **-1** for a null target and
**labels.length** when no label matches, in `execute_type_switch`,
`type_switch_match`, `primitive_match`, and `execute_enum_switch`. Unit tests in
`vm/src/vm.rs` that asserted the inverted values were corrected.

This is a general correctness fix for JEP 441 pattern switches, not Tomcat-specific.

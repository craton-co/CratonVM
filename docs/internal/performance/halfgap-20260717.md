# Benchmark baseline renewal + gap-reduction round (2026-07-17/18)

Branch `perf/halfgap-20260717` (base dev 60fbc59b4), Azure benchmark host,
worktree `/data/wt-perf-halfgap-20260717`. Goal: renew the stale README
table, then cut each row's gap vs HotSpot JDK 25 C2 (target amended
mid-round: ≥1/3 gap reduction per row, then move on).

## Why the baseline was renewed

The README's numbers no longer reproduced. Same-commit A/B (an anchor binary
rebuilt at 331b279e, the commit the old table was measured on) showed
identical code ~1.7x slower on CratonVM's memory-heavy paths while Temurin's
numbers barely moved — the host was re-provisioned around 2026-07-14 (EPYC
9V45, SMT pairs (12,13)/(14,15); pinning-width and warm-up were tested and
ruled out). Absolute times are not comparable across that boundary; every
row was re-based and ratios are the durable content.

## What landed (commits d87697f80a, d6f6426952, 287d33443e + follow-ups)

1. **Second TLAB-remnant wedge** (bt18, all alloc-heavy): steady-state
   splitting converged on 4,080-byte free-list remnants vs the 8,192-byte
   refill floor → 10.5M consecutive refill failures, ONE young GC in a 23 s
   run, every allocation through the per-object helper slow path.
   `FRAG_TLAB_FLOOR` (256 B) now shared by the guarded-refill gate and
   `refill_tlab`'s largest-block fallback ("gate and server must agree",
   one level further down than the 2026-07-14 wedge fix).
2. **Candidates-only mark oracle** (1c4aaa069 exact walk): the non-moving
   sweep materialized a `(start,end)` range for EVERY young object per
   collection (2 GiB young ≈ 50M entries ≈ 800 MB Vec) and routed every BFS
   edge through a binary search of it. Ranges are now materialized only
   where they cover a conservative candidate (roots + finalizers, early
   exit past the last one); precise heap edges mark via
   `mark_young_precise` with no oracle. Mark phase 2,098 → 474 ms. Gate:
   `StreamOnlyStressRepro` -Xmx32m (1c4aaa069's corruption face) stayed
   `badSize=0 RESULT=OK` across every run.
3. **TLS layout caches**: `types::compact_field_slot` (naked registry
   RwLock + Arc clone per JIT field access, 41% of the anchor bt18 profile)
   got the same 8-entry generation-validated ring `gen_heap`'s version has;
   `resolve_field_descriptor_byte_cached` got an 8-entry ring behind its
   1-entry probe.
4. **BLOCKGC probe cache**: `CRATONVM_DBG_BLOCKGC` was read with raw
   `getenv` on EVERY native call (PIN-UNDERFLOW guard) — ~7% of HashMap-4M,
   ~9% of StringRegex. OnceLock-cached (10 sites).
5. **OSR ldc-string wiring**: `compile_osr_artifact` bailed on ANY method
   containing a string constant ("not yet wired" `ldc_string_info`) and
   permanently OSR-denied it — `StringRegexOnly.run` interpreted its whole
   workload. Now wired with artifact-retained bytes; the failure also
   prints under `CRATONVM_DBG_JITC` (it was fully silent). The sibling
   early-compile site (~interpreter.rs:5763) is still unwired.
6. **Guarded inline-compact allocation restore**: 6599b898f had disabled
   compact-size baking in `emit_inline_tlab_new` (real Groovy stale-layout
   corruption). Restored behind a per-class layout-REPLACE counter
   (`layout_replace_guard`: fixed 1M-slot AtomicU32 table, bumped only when
   an existing class_id's layout is replaced; 3-instruction guard baked
   into the allocation site; mismatch → always-correct helper).
7. **Exact-HashMap thin direct calls**: `put`/`get` sites recognized in
   BOTH compile tiers (the OSR-tier construction site is the load-bearing
   one for once-invoked harness methods — a try_compile-only recognition
   measurably did nothing). Guard-free registration; the helper verifies
   the receiver's exact class and serves the Integer-overlay fast path with
   no `safe_native_call` wrapper, falling back to the full dispatcher for
   subclass receivers/non-Integer keys/materialized maps/redefine windows.
   Parity probe `bench/HmSemanticsProbe.java` (exact vs
   LinkedHashMap-as-HashMap, null keys/values, overwrite/absent): checksum
   3750078215 identical to JDK on both arms.
8. **TLAB-refill GC triggers — QUARANTINED**: the intended treadmill cure
   (wedge-breaker + rate-limited `needs_gc()` consult at refill time)
   reproducibly exposes a LATENT young-walk/free-list defect (5/5 wrong bt
   checksums, 676xxxxx under-count family, "cursor overshot into free
   block" / half-zeroed headers). Landed default-OFF behind
   `CRATONVM_TLAB_GC_TRIGGER`; full evidence in
   `docs/known-issues/tlab-trigger-gc-young-walk-corruption.md`. Fixing
   that defect and enabling the triggers is the next Binary-Trees lever
   (~10.5 s → consistent, and bt-default-heap parity).

## Diagnosis tooling learned/added

- A bench harness whose hot loop lives in `main` (with an indy string
  concat) gets its whole-method OSR artifact silently bailed →
  `mark_osr_denied` forever → the benchmark measures the interpreter.
  Kernels now live in their own static methods; OSR-compile failures print
  under `CRATONVM_DBG_JITC`.
- `CRATONVM_DBG_TLABMISS` / `CRATONVM_DBG_YOUNGSTATE` / gcphase were the
  discriminators for the wedge; `perf record -e cpu-clock` on the pinned
  CPU for attribution (hardware counters unavailable on this VM).

## Residuals / next levers

- Fix the young-walk/free-list latent defect → flip
  `CRATONVM_TLAB_GC_TRIGGER` default ON (Binary Trees, default-heap
  behavior, and any mid-drain collection safety).
- Kernels: OSR-tier kernel register homes landed as an OPT-IN experiment
  (`CRATONVM_JIT_KERNEL_REG_OSR=1`; default off). Arithmetic — the row it
  was built for — showed no wall-clock change: that kernel is
  long-division bound (`i/2` + `i%7` chains), so removing local load/store
  traffic doesn't move it. Checksums were correct under the flag in the
  runs taken. Matrix/Sieve remain unmeasured under the flag in a quiet
  window; the plumbing (request from `compile_osr_artifact`, real OSR
  entries for register-homed pure kernels — the trampoline already seeds
  registers from `osr_local_assignments`) is in place for the next kernel
  round. Fibonacci is recursion-dispatch bound; Sieve keeps per-element
  bounds checks (`<=`-loop BCE refusal, SECURITY FIX V17) — both need
  different levers.
- Fibonacci: recursion/self-call dispatch bound — needs its own lever.
- Sieve: `<=`-loop BCE refusal (SECURITY FIX V17) keeps per-element checks.
- HashMap residuals: boxing helper (~10%), map-native mutex+probe, the
  fallback path's `safe_native_call`.
- StringRegex: invoke-path registry lookups for non-cached natives
  (StringBuilder.append family), Matcher direct calls, second ldc site.

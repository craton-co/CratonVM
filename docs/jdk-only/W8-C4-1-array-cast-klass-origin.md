## 1. The oracle, in full

`ClassCastException`'s message is **generated by the VM**, not written by a JDK
author, so nothing but the VM can get it right — and its exact text is
load-bearing (the `checkcast` raise site in `interpreter/opcodes.rs` already
carries the story of mockk's `JvmAutoHinter` regex capturing `String` instead of
`java.lang.String` off a malformed one).

Eleven cast shapes, `java -cp out CastMsgs`, verbatim:


Three facts, and the task's framing asked which of them the code got wrong:

1. **Name form.** Arrays are printed in **JVMS descriptor form with dots**
   (`[Ljava.lang.String;`, `[[I`), never JEP 358 source form (`String[]`,
   `int[]`). CratonVM already agrees — `interpreter/lambda.rs`'s
   `cce_display_class_name` renders the descriptor and `opcodes.rs` dots it.
   **Not the defect.**
2. **Loader.** Row `I`: `[LCastProbe;` is **in the unnamed module of loader
   'app'**, not bootstrap. An array's defining loader is the *component's*
   (JVMS §5.3.3 step 2, verbatim: "If the component type is a reference type,
   the Java Virtual Machine marks C to have the defining loader of the
   component type as its defining loader"). `ClassManager`'s array synthesis
   already does this (`array_defining_loader`, C2 review P1). **Not the
   defect either** — the array class, when it exists, carries the right answer.
3. **Reachability.** Row `H`: a primitive-component array at depth 2 is still
   java.base / bootstrap, because `[[I` is an objArrayKlass whose *bottom*
   klass is the typeArrayKlass `[I`, so HotSpot takes its "klass is an array of
   primitives, module is java.base" arm.

So the module and loader rules were both already encoded. **The defect is that
the code encoding them could not be reached.**

## 2. The defect

`fn klass_origin` (`vm/src/runtime/exceptions.rs`) opened with

```rust
    let class_id = cm.find_unique_class_by_name(display_name).or_else(|| {
        let frame_class = thread.frames.last()?.class_id;
        cm.find_class_by_name_for_class(display_name, frame_class)
    })?;
```

— a lookup of **the array class itself** — and only afterwards parsed the `[`
prefix to find the component's module. `?` on that lookup collapses the whole
message: one `None` from either operand and `hotspot_class_cast_message`
returns `None`, and the funnel keeps the bare `X cannot be cast to Y` text.

W7-37 §B8 measured four of six shapes falling back to the bare form and
concluded the array arm "has never executed". §B11.1 corrected that to the
weaker and worse statement: it executes **iff something already defined that
exact array class**, so

* `RExceptions` passes the `String → String[]` row only because its own
  `static final Object AS_V_STRARR = new String[1]` indexes
  `[Ljava.lang.String;` before `main` runs;
* the same site read bare in one program and HotSpot's full string in another;
* **two of this row's three "recorded as fixed" events are explained by that
  and nothing else** — a probe that allocates the array type it is asking about
  reports the bug fixed.

That is why `CastMsgs` above adds `A2_obj_to_unseen_refarr` (`Long[]`, an array
class the probe never instantiates) beside `A_obj_to_refarr`: the two rows are
byte-identical on HotSpot and are the pair that separates a real fix from an
incidental index hit.

## 3. What was applied

`vm/src/runtime/exceptions.rs`. The lookup now happens **after** the parse, and
resolves the **component**, so no array class needs to exist anywhere:

* new `enum OriginLookup { Plain, Component, PrimitiveArray }` and
  `fn origin_lookup(display_name) -> OriginLookup<'_>`, a pure function with
  unit tests (§4);
* `klass_origin` resolves `Plain`/`Component`'s name and reads `module_name` +
  `loader_id` off *that* class; `PrimitiveArray` returns
  `java.base` / `'bootstrap'` with **no lookup at all**;
* the old post-lookup `dims` block and its `let name = class.name.to_string();`
  are deleted — the class now resolved is already the bottom component, so the
  block was recomputing what it had.

Two details worth keeping:

* **`origin_lookup` strips *all* leading `[` before stripping `L`.** HotSpot
  walks `ObjArrayKlass::bottom_klass`, so `[[Ljava.lang.String;` and
  `[Ljava.lang.String;` must print the same clause — rows `E` and `G` confirm.
* **A plain class whose name starts with `L` (`Long`) is not an array.** The
  `dims > 0` guard on the `Component` arm is what keeps `strip_prefix('L')`
  from eating it; there is a unit-test row for exactly that.

### The helper that already existed, and why it could not serve

`vm/src/runtime/interpreter/constants.rs:1055`,
`pub(super) fn array_component_class_name(name: &str) -> Option<&str>`, is the
same parse and has one caller. It could not be reused: it is `pub(super)` to
the `interpreter` module, and — the substantive reason — it returns `None` for
**both** "not an array" and "primitive-component array", collapsing the exact
distinction that decides whether `klass_origin` performs a lookup at all. The
collapse is recorded in `origin_lookup`'s doc comment so the next person does
not re-derive it.

## How to read this

One line per row: `ID (r18 tier) -- owner area -- need -- what is missing [probe / row]`. **need** is `HOST` when the row asks for a census, a measurement or a perf reading before any code (nothing to write without a build), `CODE` when the missing piece is code that can be written now (often small, but in the named owner's files), `CODE+HOST` when the code is gated on a measurement. The source text of each row is r21's (`jr21-r18-backlog-retriage-20261015.md` section 2) and the r18 page (`docs/internal/fixed-bugs/jit-backlog-triage-r18-CLOSED-20261012.md` section 3) under the same ID.

Nothing below is JIT-lane CODE work that a code-only lane can finish with confidence outside the areas other j27 lanes own (VHCOMP, INTRINS, TIER1PROP, RESIDENCY, DISPATCH2, CLONE, STRRX, REVIEW): the CODE rows are either in those areas, in non-JIT crates (collections, classloading, FFM, MethodHandle natives), or hygiene with no measured payoff.

The row mark `(unverified)` is copied from r21 section 2: r21 found that row's premise by grep and did not read it through. It is a mark on the backlog ROW. It does not say a fix went unrun, because this page claims no fix. A row that a j27 lane worked carries its own `PENDING HOST VERIFICATION` note, and that lane's page holds the recipe to run.

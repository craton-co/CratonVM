Found by: JIT round 21 wave 16, lane review-fuzz5. The probes were written without running anything: no javac, no
HotSpot, no CratonVM. Each one was checked by hand for javac errors and for HotSpot-side failures: verify errors,
uncaught exceptions, unsupported VarHandle modes, and output that depends on timing or on
`OmitStackTraceInFastThrow`. Expect a first round of fixes after the orchestrator's first javac and HotSpot run.

Conventions, as for `r21-fuzz4-probes-20261019.md`:

- Every probe is in the default package, ASCII only, and prints only deterministic facts: no timings, identity
  hashes, addresses, or scheduling-dependent values.
- Stack traces are printed only for explicitly constructed exceptions.
- Implicit exceptions (`/ by zero`, AIOOBE, NPE) print their message only in the first pass, or not at all.
- Each probe has a cold pass, a warm phase long enough for both tiers and for OSR, a deopt trigger (a class that
  was never loaded before), and then the same facts again.

**HotSpot expectation for every probe: every line identical on every arm, except a control arm marked "expected to
differ".**

Common run lines (substitute the probe name):

```
javac -d out tools/probes/jit/r21/fuzz/<Probe>.java
java     -Xmx256m -cp out <Probe>            # HotSpot 25, the reference
cratonvm -Xmx256m -cp out <Probe>            # --jdk-only (launcher default)
cratonvm --compatible -Xmx256m -cp out <Probe>
cratonvm --nojit -Xmx256m -cp out <Probe>
```

Each probe's header comment lists its extra switch arms.

## Probes

### 1. `R21Fz5FinTransitive1`: the finalizer bar when the finalizable class is loaded as a superclass

- **Risk:** review item 1. The ancestor walk of `finalizable_define_stale_ancestors` stops at a finalizable
  superclass that no listener ever saw.
  - `TLeaf extends TFin extends TBase`. `TFin` is finalizable, and `TBase(String)` is
    `this(Integer.parseInt(s))`.
  - `TBase(String)` is warmed until it compiles, on plain `TBase` objects. Then `TLeaf` is named for the first
    time, and every third argument fails to parse.
  - The `C*` chain is the control: there the finalizable class is named directly.
- **Expected (HotSpot):** `uncon=0` on every line, and `con` equal to `built`.
- **What a mismatch means:**
  - `uncon>0` on a `transitive` row only: review item 1 (the ancestor was never recorded).
  - `uncon>0` on a `control` row too: the bar itself, or the unwinder's proof.
  - `con` short of `built`: the settle loop timed out. Rerun before you file it.
- **Arm note:** `--compatible` loads application classes in the VM, which is the defect's path. Under
  `--jdk-only` the application class loader defines `TFin` through `define_class_full`, which runs the
  listener, so that arm may pass.

### 2. `R21Fz5MegaDefault1`: megamorphic interface calls into default methods

- **Risk:**
  - The megamorphic stub's service identity (`CRATONVM_JIT_MEGA_STUB_SERVICE_IDENTITY`).
  - The declaring-class frame labels of spliced inherited defaults (`CRATONVM_JIT_SPLICE_DECLARING_CLASS_FRAME`).
  - The wave-15 constant-pool dependency rule.
  - Handlers inside spliced default bodies.
- **Shape:**
  - The call site `s.score(k)` sees 8 receiver classes. S0-S5 inherit `Shape.score`, and S6-S7 inherit
    `Sub.score`, which calls `Shape.super.score`.
  - `score` calls the abstract `area` and wraps an explicit ArithmeticException into an
    IllegalStateException. `Sub.score` rethrows it unchanged on even keys and wraps it again on odd keys.
  - The late `S8` overrides `score` and `name`.
  - The cold and late passes print each exception shape once, with its probe frames (`class.method:line`) and
    message chain.
- **Expected:** `hot0..2` are equal, and `rehot0..1` are equal.
- **What a mismatch means:**
  - A `trace` line that names an implementing class instead of `R21Fz5MdShape` / `R21Fz5MdSub` for a default
    frame: the splice frame label.
  - A missing middle frame (`R21Fz5MdSub.score`): the mega-stub identity, as in `R21Fz2SpliceDeep2`.
  - A sum or count difference after `late` only: `S8` did not withdraw a splice of `Shape.score` or
    `Sub.score`.

### 3. `R21Fz5HiddenOsr1`: two hidden classes from the same bytes, then the ordinary class of that name

- **Risk:**
  - The wave-14 hidden self-reference routes (`CRATONVM_JIT_HIDDEN_SELF_BY_ID`).
  - The wave-15 lock-free hidden-class bitmap (`HiddenClassBits`).
  - The verifier's hidden self name.
- **Shape:**
  - Two hidden payloads are defined from the same class bytes. Each has an OSR-compiled static loop that calls
    its own private static `step` and throws and catches inside the loop, and each has its own `sCount` /
    `sAcc`.
  - The hidden instances share a megamorphic `IntUnaryOperator` site with a lambda, an anonymous class and,
    later, the ordinary class.
  - The `plain` line loads the ordinary `R21Fz5HoPayload` from the class path, and the loops then run again.
  - The payload's own type appears in no descriptor and in no array type, so on HotSpot the hidden copies
    resolve their own name only through `this_class`.
- **Expected:** every count is a pure function of the calls. `h1`, `h2` and `plain` each count only their own
  calls.
- **What a mismatch means:**
  - Counts that move between `h1`, `h2` and `plain` after the `plain` line: a by-name answer for a hidden
    self-reference, the `R21Fz3HiddenAccess1` `HN` shape.
  - The control arm `CRATONVM_JIT_HIDDEN_SELF_BY_ID=0` is expected to differ.

### 4. `R21Fz5VhUnsafeMix1`: VarHandle, Unsafe and the field updaters on the same fields

- **Risk:**
  - The VarHandle fold, and the unsafe field-cell arms (`CRATONVM_JIT_UNSAFE_FIELD_RMW_INLINE`, `..._CAE_INLINE`,
    `..._BITWISE_INLINE`, `..._FIELD_CELLS_BYTE_OFFSETS`) when two doors meet on one field: a cached load, a
    wrong width (byte and short neighbours of a volatile int and a volatile long), or a stale value after the
    deopt.
  - Counted loops with wrapping bounds: an int loop that ends only when `i += 7` wraps past MAX_VALUE (715
    trips), and a long loop that wraps through Long.MIN_VALUE (68 trips).
- **Deopt trigger:** a never-loaded `Holder` subclass becomes the receiver.
- **Errors row:** a wrong receiver class through the VarHandle and through a raw updater (CCE), a null receiver
  (NPE), and an array index out of range (AIOOBE). Class names only.
- **Note:** JDK 25 prints a one-time `sun.misc.Unsafe` deprecation WARNING on stderr. Diff stdout only.
- **What a mismatch means:**
  - A `cold` difference: the interpreter's Unsafe or VarHandle arm.
  - A `hot` difference with an equal `cold`: a compiled arm, at the wrong offset or width, or with a load
    reordered across another door's store.
  - `late` only: the receiver check or the deopt.

### 5. `R21Fz5DeoptStorm1`: six subclasses arrive while compiled loops depend on there being one

- **Risk:**
  - Class-hierarchy dependencies and their withdrawal at each define (`invalidate_for_new_subtype`,
    `CRATONVM_JIT_SUBTYPE_DEFINE_SCOPED`).
  - The wave-15 rule that names the constant-pool class (`apply` is declared in `R21Fz5DsBase` and called
    through `R21Fz5DsOp`).
  - A running OSR activation, on a second thread, whose dependency dies under it.
- **Shape:**
  - The ops arrive in order. `Op1` overrides `step`. `Op2` overrides `apply`. `Op3` throws from `step`, and the
    loop catches it. `Op4` and `Op5` add levels. `Op6` overrides both `step` and `apply`.
  - The worker thread only ever sees `Op0` objects and runs a fixed 40 rounds, so its hash does not depend on
    how the arrivals interleave with it.
  - The int loop wraps downward through MIN_VALUE (20 trips), and the long loop wraps upward through MAX_VALUE
    (n + 4 trips).
- **What a mismatch means:**
  - A `loadK` difference: a body compiled under the old hierarchy survived the arrival of `OpK`, or resumed
    with the wrong locals.
  - A `worker` difference: the OSR activation deopted wrongly under a concurrent define.
  - The control arm `CRATONVM_JIT_SUBTYPE_DEFINE_SCOPED=0` must match too.

### 6. `R21Fz5SpliceRethrow1`: catch, wrap, rethrow and finally inside small spliced callees

- **Risk:**
  - Handlers inside spliced callees (`JitLocalHandlerSite`).
  - The deopt-resume of a throw from a nested splice.
  - Precise rethrow (`throw t` of a caught Throwable keeps its original trace).
  - A `return` in a `finally` that discards the exception.
  - try-with-resources whose `close()` throws, alone or as a suppressed exception.
  - A loop index that starts 2000 below MAX_VALUE and wraps, so that `i % 70` turns into a negative array index.
- **Deopt trigger:** a never-loaded `Res` subclass whose `close()` always throws.
- **Expected:** `hot0..2` are equal and `rehot0..1` are equal. The `trace-hot` lines have the same callee frames
  as the `cold` ones; only the driver frame differs.
- **What a mismatch means:**
  - A count difference (`wrapped`, `rethrown`, `finallyRet`, `suppressed`, `closeOnly`, `nested`): a handler of
    a spliced callee was skipped or ran twice, or the `finally` return was lost.
  - `fin=` differs: a `finally` ran a different number of times.
  - A trace frame difference in `trace-hot` only: the compiled frame labels or lines of the splice.

## Not covered

  deterministic.
- Redefinition (review items 2, 5 and 7). These need an agent (`Instrumentation.redefineClasses`), which a
  self-contained probe cannot load without a jar manifest. A follow-up could add one under
  `tools/probes/jit/r21/agent/`.

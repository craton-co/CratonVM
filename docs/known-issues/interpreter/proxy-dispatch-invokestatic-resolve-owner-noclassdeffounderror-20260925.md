**Status:** Active working issue under investigation / fix verification.
**Filed:** 2026-09-25
**Affected commit:** `74c322b54db9ce40e804779a0922395d0f9dc17c` ("WIP interpreter wave 7 (unverified)")

## 2. Root Cause Analysis

### 2.1 The Synthetic Proxy Dispatch Contract

In `cratonvm-classloading/src/proxy_gen.rs`, dynamic proxies generated by CratonVM delegate proxied method calls via bytecode instruction:

```bytecode
INVOKESTATIC java/lang/reflect/Proxy$Dispatch.invokeProxy:(Ljava/lang/Object;Ljava/lang/reflect/Method;[Ljava/lang/Object;)Ljava/lang/Object;
```

As explicitly documented in `classloading/src/proxy_gen.rs:82-92`:
> "Every emitted method body ends in `INVOKESTATIC java/lang/reflect/Proxy$Dispatch.invokeProxy`, and `java/lang/reflect/Proxy$Dispatch` **is never defined as a class**. It exists only as an owner-name key in the native registry (`register_reflect_proxy_natives`); nothing calls `ensure_synthetic_class` for it, so `get_loaded_class_id` returns `None`. A member-access check that resolves the methodref's owner `Class` before checking will not find one... a stricter wiring that instead *loads* the owner turns every dynamic-proxy call in the VM into `NoClassDefFoundError`."

Furthermore, in `native-api/src/no_image_receiver.rs`:
`java/lang/reflect/Proxy$Dispatch` is cataloged as a synthetic no-image receiver without underlying classfile bytecode.

The native method is registered in `cratonvm-native-builtins/src/reflect_annotations.rs` (`register_reflect_proxy_natives`) with `NativeKind::Bridge`:

```rust
registry.register(
    "java/lang/reflect/Proxy$Dispatch",
    "invokeProxy",
    "(Ljava/lang/Object;Ljava/lang/reflect/Method;[Ljava/lang/Object;)Ljava/lang/Object;",
    native_proxy_dispatch_invoke,
);
```

### 2.3 The Interaction with Launcher Defaults

In `vm/src/config.rs`:
The launcher default execution policy was recently changed to strict/JDK-only (`VmConfig::for_launcher()` sets `CompatibilityMode::JdkOnly`), unless the caller explicitly passes `--compatible`.

When `run-hibernate-reactive-suite.sh` invoked CratonVM:
`VMFLAGS_BASE=(--java-home "$JDK" --Xmx "$CV_XMX")`
Notice `--compatible` was omitted.

Consequently:
1. `shared.config.is_jdk_only()` evaluated to `true`.
2. `resolve_owner_fully` evaluated to `true` (despite `is_native == true`).
3. `dispatch_static.rs` invoked `shared.load_class_concurrent("java/lang/reflect/Proxy$Dispatch")`.
4. Because `Proxy$Dispatch` is a synthetic dispatch hook and has no classfile in the JDK, class loading failed with `ClassNotFound`.
5. `convert_class_not_found` converted the error into `java.lang.NoClassDefFoundError: java/lang/reflect/Proxy$Dispatch`.

## 3. Verification & Resolution

### 3.1 Verification with `--compatible`

When invoked with `--compatible`:
`resolve_owner_fully` evaluates to `false` because `!is_native` is `false` and `is_jdk_only()` is `false`. The class loading attempt is bypassed, and the method dispatches directly to `native_proxy_dispatch_invoke`.

Test verification on host `20.80.105.49`:
```bash
/data/cratonvm/target/release/cratonvm \
  --java-home /data/toolchain/jdk-25 \
  --compatible \
  --Xmx 1500m \
  -XX:+UseG1GC \
  @common.args \
  -Dcraton.batch=1 \
  CratonRunner org.hibernate.reactive.annotations.tests.FilterByDbTypeOnMethodTest
```
Result:
```text
@@RESULT org.hibernate.reactive.annotations.tests.FilterByDbTypeOnMethodTest found=8 started=4 ok=4 failed=0 aborted=0 skipped=4 ms=485
@@BATCHEND failed_classes=0
[cratonvm] main-vm run() returned Ok — VM main exiting normally
```
All 4 executable tests pass in 485 ms with 0 failures.

### 3.2 Proper Fix for Strict Mode

In strict/`--jdk-only` mode, the VM must distinguish between real JDK native classes (which declare static natives and must have their real class loaded and `<clinit>` executed) and internal synthetic VM dispatch hooks (which have no class bytes by design).

In `vm/src/runtime/interpreter/dispatch_static.rs`:
```rust
let is_synthetic_dispatch_hook = method_class_name.as_ref() == "java/lang/reflect/Proxy$Dispatch";
let resolve_owner_fully = (!is_native || shared.config.is_jdk_only()) && !is_synthetic_dispatch_hook;
```

This prevents strict mode from attempting to resolve a nonexistent classfile for VM-internal synthetic hooks.

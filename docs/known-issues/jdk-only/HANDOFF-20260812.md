## 2. The one thing to understand before doing anything else

**In this VM, changing how a native is classified is not the same as changing
what runs.** `register()` is last-write-wins, and `NativeKind` is *ambient* —
set by `set_category`/`with_category` around a block, not per registration.

Nine separate lanes today shipped or nearly shipped a fix that was **inert**:

* a `Bridge` retag that bought a census line and changed no dispatch;
* `nextGaussian` fixed on the registrar that loses (`securerandom` registers last);
* `LogRecord.<init>` in `RETIRED_SHADOW_TRIPLES` since 08-11 doing nothing,
  because the retag arm fires only at `effective_category() == Bridge` and that
  function's ambient kind is `Intrinsic`;
* **`Runtime.exit(I)V` exiting 0 for every status** — the correct body was
  already registered in `lang_system.rs`; a later `lib.rs` line overwrote it.

Before writing a fix: grep **every** registration of the triple, decide which
wins on which boot path, and check the ambient kind around the block.

**Do not settle registrar order by indentation.** Four lanes were burned by
brace-scanning today: column-0 `}` closers that close nested helpers, a counter
that drifted over 24k lines, and a backslash-newline inside a string literal
that swallowed six lines. The lanes that got it right validated their scanner
against ground truth *first* (depth 0 at EOF, line count matches the file, every
`fn NAME` verified on its claimed line) and then re-read every cited line with
`sed`.

suite run, however green**.

## 5. Traps specific to this codebase

* **`--features synthetic-jdk` is a BUILD feature; `--synthetic-jdk` is a
  RUNTIME mode.** They are not the same and conflating them has produced wrong
  conclusions twice. A feature build still runs both `--real-jdk` and
  `--jdk-only`.
* **A slot count cannot identify a layout.** `HeapByteBuffer`'s `6` and
  `thread_start`'s old check are witnesses; widening them darkens every indexed
  fallback behind them.
* **`report_layout_alias` sees allocation width only.** It structurally cannot
  see a read of the *wrong field* — that read is in bounds, so the `gc::guard`
  discriminator misses too. `native-api/src/read_alias.rs` is the second
  instrument; its first census found **32 slot maps disagreeing with the real
  JDK layout, 23 agreeing**.
* **`direction=under` cannot report a short object.** The allocator clamps two
  lines after the detector runs. The genuinely-short population reaches
  `alloc_object` with `real_fields == 0` and is reported as `undeclared`; the
  ratchet bound is **28, may only go down**.
* **`cargo check --all-targets` runs NO tests**, and `vm/src/vm/tests.rs` is
  synthetic-jdk-ONLY — coverage placed there goes dark on a default build.
* Any `CRATONVM_*` name needs FOUR things or `cargo test -p cratonvm-types` goes
  red: `types/src/flag_groups.rs`, `types/tests/flag-surface.txt`, a row in
  `docs/flag-tokens.md`, and regenerating `docs/config/flag-inventory.md`.
* **Cite internal docs prefix-less and as PLAIN TEXT**, never a markdown link —
  `types/tests/doc_citation_paths.rs` scans Rust comments too.

## 6. Orchestration lessons, paid for

* **Check `BUILD_RC` explicitly.** A completion notification reported exit 0 for
  a build that failed with `rc=101`, because an `echo` was last in the pipeline.
  Also compare the binary's mtime against `git log -1` — that caught three
  separate stale-binary situations, one of which had already produced a wrong
  conclusion.
* **Do not mutate the tree while a measurement is running.** A merge landed
  mid-run and the two suite arms compiled different fixture sets; neither number
  was quotable. Agents reading the shared `target/release/cratonvm.exe` while it
  is rebuilt see results swing with nothing under their control changing — one
  lane caught this and pinned a private copy. Tell agents to do that.
* **Never `git add -A` in the main worktree.** Another session's uncommitted
  work lives there; it was swept into a commit once and had to be backed out.
  Explicit paths only.
* **Do not union prose conflicts mechanically.** Doing so three times produced a
  README section headed "FULLY CLOSED" listing ten live records, with one record
  appearing twice on opposite verdicts. Compose by key, or take the side that
  did the verification.
* **Brief agents to check whether the recorded defect is real before fixing it.**
  Today: an `SSLEngine` 7-vs-2 corruption that did not exist, a `--add-opens`
  parser bug that did not exist, three access-enforcement records already fixed,
  and nine of nine "unapplied" FJP patches already applied.

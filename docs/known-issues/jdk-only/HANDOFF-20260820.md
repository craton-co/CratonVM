## 0. The one thing to read if you read nothing else

**Three P0/P1 row remedies were disproved today, by measurement, in three
independent lanes.** Not "not done yet" — *disproved*. If you plan against those
rows as written you will spend a wave on changes that cannot work:

| row | what it prescribes | why it cannot work |
|---|---|---|
| **Wholesale `Bridge` over-tagging** | retag the map/set ownership cluster whole | `NativeKind` cannot move this cluster at all. `SyntheticStub` acts in exactly ONE place — `register_inner`'s `JdkOnly` arm — and removes a *registration*, not a Rust function. **168 direct Rust calls** from 18 files in two other crates, **45 `try_alloc_concurrent_synthetic` sites** that allocate under the REAL class id, and **6 JIT direct helpers** bypass the registry entirely. After a retag those objects meet real bytecode over a real, empty `table` and answer **absent** — a silently empty map, no error, no failing vector. (`H4-1` §1) |
| **NIO, files, networking** | move the natives from the abstract public API onto the `sun.nio.ch.*Impl` classes | They cannot move: **the VM fabricates receivers whose class name IS the abstract class**, at 13 named allocation sites. (`H5-1` §3) |
| **Native-first dispatch and hard-coded overrides** | "reconcile the two lists, do not merge them" | The premise expired **2026-08-04**. `COPY 1 OF 2` is gone (`b90f9a614`); there is ONE predicate with twelve entries, not two with ten and eleven; `StringJoiner` is protected on both paths; and `real_protected_stub_class` is not in the file the row names. **The shape they share.** All three read as *tagging* problems and all three are
*object-model* problems one layer down: the VM owns state, or mints receivers,
that a tag cannot reach. `G88-1` §5 was right that the unit of work is the
ownership cluster rather than the registrar — and it stopped one level short,
because the cluster is not confined to Java dispatch.

**Consequence for the goal: the P0 table cannot reach CLOSED by retagging.**

## 4. What actually landed today

* **A live GC hazard fixed** (`H6-1`): `init_runtime_mxbean_fields` wrote slot 0
  ← `Object` and slot 1 ← `Int` into a real `java.util.ArrayList`, whose JDK 25
  layout is `0 modCount(int) | 1 elementData(ref) | 2 size(int)`. An `Int` in a
  reference slot is a value the collector marks and moves. The file's other two
  `ArrayList` allocations already wrote by name, so the exception was invisible
  to a whole-file grep.
* **The FILETIME epoch** (`H2-1`): `WindowsFileAttributes` stores Windows
  FILETIME (100 ns since 1601-01-01) and CratonVM wrote Unix millis into those
  fields and read them back the same way — self-consistent, agreeing with
  nothing. `1609459200000` ticks *is* the `1601-01-02T20:42:25.920Z` the arm
  printed. Eight `sun/nio/fs/` shadows retired; **verified live, not inert** (all
  eight print `[JDK-ONLY-REFUSED]`, `RFileTimes` passes 68 checks).
* **One duplicate registration deleted** (`H5-1`): `FileInputStream.read([BII)I`
  was registered twice in one function and the later ambient-`Bridge` line
  silently won. The comment defending it was false — it claimed two different
  callbacks; both named `native_fis_read_bytes`.
* **Seven `java.util.function` stubs deleted** (`H3-1`), reachability measured

* **The JMX ambient registrars pinned** and `ObjectName`'s canonical-name slot

**`CRATONVM_ENFORCE_NATIVE_SHADOW=<prefix>` prices a retirement before anyone
attempts it, for one env var and no build.** That instrument existed for months
and had only ever been swept whole-VM (`all` → 1/36) or over a 36-vector screen.

Three things follow:

1. **The families are not equally entangled** — a 23× spread. Every previous
   argument, including `G88-1` §5's, treated the cluster as one body.
2. **`RMapGcStress` is one defect with four faces**, not four defects:
   `iterated 1 != 3000` under `HashMap` and `LinkedHashMap`, a lost value under
   `Hashtable`, an NPE from `Iterator.next()` under `HashSet`. Real bytecode
   iterating a table the VM never populated — 3000 inserts went to a side
   structure. Diagnose it once and four rows re-price.
3. **The migration order inverts the P0 row's.** It says `native-collections`
   "last and subdivided by collection family". Subdivided, yes — but `HashSet`
   and `Hashtable` are the cheapest things in the cluster and are queued behind
   the most expensive.

**A zero is permission to attempt and measure, not permission to skip
measuring.** 104 vectors is not the world: the corpus has no AWT vector at all
(`G79-1`), and `G90-1` §5 is the standing instance of a screen passing what the
wider arm rejected.

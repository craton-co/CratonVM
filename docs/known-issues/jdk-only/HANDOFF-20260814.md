## 3. How to work here

```bash
# build (30–45 min; stamp HEAD first so the binary stays attributable)
git rev-parse HEAD && date -u '+%Y-%m-%dT%H:%M:%SZ'
cargo build --release -p cratonvm-cli 2>&1 | tail -3; echo "BUILD_EXIT=${PIPESTATUS[0]}"
```

- **Read `BUILD_EXIT` from the line the command prints itself.** The task
  wrapper reports its own exit code, not the build's; that has produced wrong
  claims before.
- Verify **no `.rs` changed inside the build window** before attributing a
  measurement to a binary:
  `find . -name '*.rs' -newermt '<build start>' -not -path './target/*'`
- Compile-check without disturbing the release dir:
  `cargo check --workspace --tests --target-dir /c/craton/target-fcheck`
- Run one vector: `ONLY="RJdkBridge1" bash regression-suite/run.sh`
- Run it directly to see the failing assertion:
  `./target/release/cratonvm.exe --java-home "$JAVA_HOME" -cp regression-suite/build RJdkBridge1`
- **Never edit `run.sh` while a suite is running** — bash re-reads the file at
  its saved byte offset and will execute garbage.

## 4. The method that actually found things

Every one of the twelve measured fixes came out of the same loop:

1. Run the vector, take the **first** failing assertion.
2. Write a probe that measures **the whole family on both VMs**, not the one
   row. This is where the value is: the `Properties` null axis was 0 of 15,
   `Vector`'s index surface was six message conventions across five methods,
   and `%t` was 79 refusing cells. A one-row fix would have found one row.
3. Diff CratonVM against HotSpot with line endings normalised (`tr -d '\r'`).
4. Fix, rebuild, re-diff, commit only when the diff is empty.

**Use `--dump-native-registry` to answer "which body runs".** Reading cannot
settle it and comments actively lie about it:

```bash
./target/release/cratonvm.exe --java-home "$JAVA_HOME" \
    --dump-native-registry out.json -cp <cp> <Main>
# rows carry: class, name, descriptor, kind, registered_by, overwrote,
#             owns_slot, invocations
```
`owns_slot=true` plus a non-zero `invocations` is proof. Flags must precede
the main class or they are ignored silently, with exit 0 and no file.

## 5. Traps that cost real time here

- **A green build proves you broke nothing, not that you did something.**
  Twice a change compiled, built and did nothing: once a fix landed in a body
  with `invocations=0`, once a scripted edit matched zero sites. Only
  re-measuring caught both.
- **Scripted edits land on the wrong twin.** A repoint matched the first
  occurrence in the file and patched `ArrayList` instead of `Vector`. Always
  confirm which class the patched line belongs to.
- **A line number proves where a body is, never that it runs** (F14-1's
  correction note).
- **Do not generalise a contract from three rows.** `Properties`' null rule is
  two rules; `Handler.setFilter(null)` and `Logger.setLevel(null)` are *legal*
  where three sibling setters throw; `Vector.subList` keeps the plain
  exception where every sibling throws the subclass. Each blanket rule would
  have broken working paths.
- **Messages often cannot be derived, only transcribed** — `"inStream
  parameter is null"`, `"0 >= 0"`, `"Array index out of range: 0"`,
  `"arraycopy: source index -1 out of bounds for object array[10]"`.
- **Unquoted heredocs eat backticks.** Use `<<'EOF'`. (This document's own
  first draft was mangled that way.)
- `grep -c $'\r'` matches every line in this shell and will report a pure-LF
  file as CRLF. Use `tr -cd '\r' < f | wc -c`.

## 6. What to pick up next, in the order I would do it

1. **Keep driving `RJdkBridge1` and `RJdkIntrinsics3`.** The loop in §4 works;
   each cycle is roughly one build. Nothing clever is needed.
2. **`java/util/Hashtable`'s null axis — 7 of 9 rows diverge.** Measured, not
   fixed. It is a *separate slot* from `Properties`, partly served by generic
   Map natives shared with `HashMap`, which legitimately accepts null keys. It
   needs receiver-routing (`is_hashtable_receiver` already exists and is the
   right shape), not a copied guard.
3. **`ConcurrentHashMap`'s invented message** — `"ConcurrentHashMap does not
   permit null keys"` has never been compared with the oracle.
4. **The 2,412 drifting triples** F34-1 found: registered by *both* a
   synthetic-only family and a shipping pass, so the two modes run different
   code. F34-1 gated the *population*; the drift itself is ungated. This is
   the largest known unexamined surface.
5. **`InheritableThreadLocal` capture timing** (F41-1 §6). Deliberately not
   touched: the current behaviour is a documented workaround protecting every
   `Executors` path, and correcting it needs interpreter-level tracing of why
   `Thread(ThreadGroup, Runnable, String)` drops the constructor copy.

## 7. Things that are true and easy to disbelieve

- `RJdkIntrinsics2` once failed the differential with **every assertion
  passing** — the whole diff was one em-dash, because HotSpot's `System.out`
  mangles it through the Windows console code page and CratonVM emits correct
  UTF-8. Non-ASCII in a *printed* check label makes the oracle comparison
  encoding-dependent. Keep labels ASCII.
- `native-builtins` depends on `native-io`, so when `native-io` fails to
  compile **nothing downstream is checked at all**. "Everything else compiled"
  is not a statement you can make from a failing build.
- A sibling session edits this worktree concurrently. Commit by explicit path;
  a blanket `git add -A` here previously captured a mid-write file and left
  HEAD unparseable.

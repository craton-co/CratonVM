# Phase 1: the measurement after the fixes

**Measured 2026-08-12 on a release binary built from this branch
(`cargo build --release -p cratonvm-cli`, exit 0, 0 errors, 17m46s), against
HotSpot 25.0.3+9 as oracle, same host, same session, same class files.**

The "before" is `P1-BASELINE-20260812.md`, taken on the pre-wave binary.

## The sweep

| probe | HotSpot | before | after |
|---|---|---|---|
| `P1Witness` (java.sql, `getenv`, SSL construction) | 8 / 0 | 2 / 6 | **8 / 0** |
| `P1Tls` (real loopback TLS round trip) | 6 / 0 | 3 / 1 | **6 / 0** |
| `FabReach` (iteration, functional, proxies, sockets) | 17 / 0 | 15 / 2 | **17 / 0** |
| `FabReach2` (streams, FFM, NIO, HttpServer, JMX) | 16 / 0 | 15 / 1 | **15 / 1** |
| `FabReach3` (Enumeration, async channels, `Runtime.exec`) | 7 / 0 | 3 / 4 | **7 / 0** |

**53 of 54 checks now match HotSpot exactly**, from 28 of 54 before.

Eight of the nine blocking families are closed and verified by measurement:
`java.sql`/`Atomic*FieldUpdater`, `System.getenv()`, the TLS stream receivers,
`Consumer.andThen`/`Predicate.and-or-negate`, `ConcurrentHashMap.keys()`,
`Hashtable.keys()`, `AsynchronousFileChannel`, and all six `Runtime.exec`
overloads.

## The census moved exactly as predicted

`compatibility-class-requested` fell **19 → 6**, and the six survivors are
precisely the recovered-from set the "a request is not a failure" analysis
named:

```
cratonvm/stream/LazyOp          <- native-collections/src/lib.rs:18223
java/util/ArrayDeque$Itr        <- native-collections/src/lib.rs:35742
java/util/Enumeration$Impl      <- native-builtins/src/classloader.rs:6074
java/util/HashMap$KeyItr        <- native-collections/src/lib.rs:13623
java/util/LinkedList$Itr        <- native-collections/src/lib.rs:33133
java/util/TreeSet$Itr           <- native-collections/src/lib.rs:43546
```

Every one is requested, refused, and **recovered from** — the corresponding
Java passes. Not one names `vm/src/vm/vm_init.rs`, confirming the boot block no
longer asks. `Enumeration$Impl`'s requester is now `classloader.rs:6074`, the
funnel *with* the fallback, rather than the raw allocator that had no landing.

A lane predicted this would stay at 6 rather than dropping to 4, because
`try_alloc_synthetic` records the violation **before** refusing and the
fallback runs after. That prediction was right, and it matters: **the census
counts requests, and a fixed family stops being fatal without stopping being
counted.**

## The ninth family: fixed at the carrier, and it exposed a crash

`java/lang/foreign/DowncallHandle` is gone. The carrier is now a real
`java.lang.invoke.MethodHandle` and it matches HotSpot field for field:

```
              CratonVM                          HotSpot
handle class  java.lang.invoke.MethodHandle     BoundMethodHandle$Species_LLLL
handle type   (MemorySegment)long               (MemorySegment)long
```

But `mh.invoke(segment)` **SIGSEGVs**. Three states, cleanly attributed:

| binary | flags | result |
|---|---|---|
| pre-fix | `--enable-native-access` | `NoClassDefFoundError: DowncallHandle`, rc 1 |
| post-fix | *default* | real handle, correct type, clean `IllegalCallerException`, rc 1 |
| post-fix | `--enable-native-access` | **SIGSEGV, rc 139** |

**This is newly reachable code, not a regression in something that worked** —
the old binary never got past `downcallHandle`, so the invoke path had never
run. The default configuration is strictly better than before: a clean typed
exception from the Panama gate instead of a `NoClassDefFoundError` about a
class no JDK declares.

It is still recorded as **not fixed**. A crash is worse than an exception, and
an application that enables native access reaches it. Saying "nine of nine"
here would be counting the carrier and ignoring the call.

## What this does and does not license

**Does:** the Phase 1 mechanism — an essential-set native asking for a
fabricated receiver and killing the application at its own call site — is
closed on every route these 54 checks take. JDBC class loading, `System.getenv`,
a real TLS round trip, the core functional interfaces, the legacy `Enumeration`
getters, async file channels and `Runtime.exec` all work under `--jdk-only`.

**Does not:** 54 deterministic checks are not an application. The roadmap's own
definition of done is a Spring Boot application, a servlet container serving
HTTPS, and a JDBC workload each running to completion — none of which has been
run. The corpus runner landed this session and **no corpus has been run under
`--jdk-only` yet.** That is the next measurement, and it is the one that can
still overturn this page.

Also unchanged: the census's 229 `native-shadows-bytecode` rows are Phase 2 and
untouched, and an ambient-`Intrinsic` block is invisible to that census by
construction — which is how `Math.min(1.0, NaN)` returned `1.0` for an unknown
length of time.

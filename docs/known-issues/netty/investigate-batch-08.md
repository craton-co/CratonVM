# netty — investigate batch 08 of 13

**RESOLVED (2026-08-12).** All 15 classes now match stock HotSpot test-for-test
on the Linux host. Measured against a JDK 25 HotSpot baseline for every class,
which is what separated the three groups below — most of this page was never a
CratonVM defect.

**One real CratonVM bug, fixed:** `Http2MultiplexTransportTest` **hung** (not
"was slow": with JUnit's timeouts disabled HotSpot finished the class in 2.6 s
and CratonVM never finished at all). CratonVM's rustls/ring TLS stack rejected
the EC server identity that `java.security.KeyPairGenerator("EC")` produces, so
ALPN never negotiated `h2` and the test's latch was never counted down. See
[ec-server-identity-rejected-jdk-pkcs8-v1-20260812.md](ec-server-identity-rejected-jdk-pkcs8-v1-20260812.md).
Every EC server *and* client identity generated by the JDK was affected, not
just this test.

**Nine classes were already fixed** by the `StackWalker$Option` enum repair that
closed [batch 07](investigate-batch-07.md) — `StreamBufferingEncoderTest`,
`Http2MultiplexHandlerTest`, `Http2StreamChannelBootstrapTest`,
`HttpToHttp2ConnectionHandlerTest`, `InboundHttp2ToHttpAdapterTest`,
`UniformStreamByteDistributorTest`, both
`WeightedFairQueueByteDistributor*Test`, and `MqttCodecTest`. They needed
nothing from this page.

**Five classes fail identically on HotSpot** and are harness gaps, not VM
defects:

* the three `NativeImageHandlerMetadataTest`s (http2, memcache.binary, mqtt)
  want GraalVM metadata at a path built from Maven group/artifact system
  properties Surefire sets and the fork-per-class runner does not — the path in
  the failure message literally reads `.../native-image/null/null/...`;
* `UniformStreamByteDistributorFlowControllerTest` and
  `WeightedFairQueueRemoteFlowControllerTest` need `-ea`, which the harness does
  not pass. **This one hides a second, genuine CratonVM defect:** with `-ea`
  HotSpot goes 34/34 while CratonVM stays at 28/34, because CratonVM parses
  `-ea` and throws it away even though it implements assertion status behind an
  env var. Filed as
  [ea-flag-ignored-so-assert-never-fires-20260812.md](ea-flag-ignored-so-assert-never-fires-20260812.md);
  sequence the harness change after the VM fix or 12 matching failures become 12
  CratonVM-only ones.

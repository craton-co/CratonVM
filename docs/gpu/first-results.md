# GPU-offload first results

This file is the **acceptance gate** for Part J of the GPU-offload
plan. It will be filled in on a machine that actually has an NVIDIA
GPU — the development machine this work was written on has none, so
the table below is intentionally a placeholder.

## Procedure

On a CUDA-12.x Windows x64 box with an NVIDIA GPU:

```powershell
# Build with the real driver bindings.
cargo build --release -p cratonvm-cli --bin cratonvm --features gpu-driver

# CPU baseline.
./target/release/cratonvm.exe --classpath test_classes/gpu Benchmark 16777216

# GPU run.
./target/release/cratonvm.exe --gpu --classpath test_classes/gpu Benchmark 16777216
```

Both invocations emit a single line of the form:

```
mode=auto n=16777216 elapsed_ns=<NS> out[0]=<V0> out[n-1]=<VN1>
```

## Acceptance criteria

1. **Correctness (non-negotiable):** `out[0]` and `out[n-1]` are
   identical between the CPU and GPU runs. The data fed to
   `EligibleVectorAdd.vectorAdd` is generated by the deterministic
   LCG in `Benchmark.main`, so any mismatch is a kernel bug.
2. **Speedup:** at `n = 1 << 24` (16 Mi elements) the GPU run's
   `elapsed_ns` is strictly less than the CPU run's. Target ≥ 2×.
   Smaller speedups are *not* a fail — file a follow-up to look at
   marshalling overhead, but do not falsify the number.
3. **No regression:** `cargo test --workspace` (no features) still
   passes; `cargo test --workspace --features cratonvm-cli/gpu` builds
   cleanly even on the GPU box (some tests will be `#[ignore]` until
   the runtime is wired).

## What "pending" means

The development machine this implementation was written on has no
NVIDIA GPU. All sub-parts (A, B, C, D, F, G, H, I) were implemented
and tested on CPU-only paths with the `gpu-offload` feature gating
the entire GPU code path out of the default build. Part E (the
interpreter integration that actually launches kernels) is the next
session's work; once it lands and the runtime is then exercised on
a GPU-equipped machine, the row above is filled in.

Anyone running this on a GPU box: please **paste real numbers in the
row above** (don't synthesise). If correctness fails (`out[0]`
mismatch), file an issue — do not bury the failure.
